# НУШ Assessment Generator

Цей навик допомагає вчителю інформатики створювати тести, контрольні та діагностувальні роботи, а також квізи відповідно до груп результатів навчання НУШ. Завдання сумісні з платформою Classtime.

---

## Робочий процес

### Фаза 0: Підготовка гілки

Перед початком будь-якої роботи:
1. Переконайтеся, що знаєте клас, тему та тип матеріалу.
2. Сформуйте назву гілки у форматі `<клас>-assessment-<тема-slug>`, де `<тема-slug>` — короткий slug теми латинськими літерами з дефісами (наприклад, `6-assessment-algorithms`).
3. Оновіть `main` та створіть гілку:
   ```bash
   git checkout main && git pull origin main && git checkout -b <назва-гілки>
   ```

---

### Фаза 1: Збір вхідних даних

Запитайте у користувача наступне, якщо не надано:

1. **Тип матеріалу:** тест, контрольна робота, діагностувальна робота або квіз.
2. **Тема** (наприклад, "Алгоритми", "Безпека в мережі").
3. **Клас** (5–12).
4. **Кількість завдань** (за замовчуванням: 10–12 для тесту, 6 на кожну групу результатів навчання для діагностувальної роботи, 6–8 для квізу).
5. **Джерело матеріалу** (необов'язково): конкретні уроки з репозиторію (`content/<клас>/`). Якщо вказано — використовувати **виключно** матеріали з цих уроків.
6. **Два варіанти?** Генерувати два варіанти лише якщо користувач явно попросив.

> **ВАЖЛИВО — Групи результатів навчання:**
> Якщо користувач не вказав явно, які групи результатів навчання має охоплювати матеріал, **обов'язково запитайте** перед генерацією. Це критично для методичної відповідності.
>
> Доступні групи (докладніше — у `skills/nush-assessment-generator/references/learning-outcomes.md`):
> - **Група 1:** Працює з інформацією, даними, моделями
> - **Група 2:** Створює інформаційні продукти
> - **Група 3:** Працює в цифровому середовищі
> - **Група 4:** Безпечно та відповідально використовує ІТ

---

### Фаза 2: Аналіз матеріалу (якщо вказано уроки)

Якщо користувач вказав конкретні уроки:
1. Прочитайте відповідні файли планів (`content/<клас>/plans/`) та/або презентацій (`content/<клас>/`).
2. Виокремте ключові поняття, терміни, навички та практичні задачі з кожного уроку.
3. Генеруйте завдання **виключно** на основі цих матеріалів — не додавайте понять поза межами прочитаного.
4. Зазначте у заголовку файлу, на основі яких уроків складено матеріал.

---

### Фаза 3: Генерація завдань

#### 3.1 Розподіл по групах результатів навчання

Рівномірно розподіліть завдання між усіма обраними групами результатів навчання. Якщо обрано 2 групи і 10 завдань — по 5 на кожну.

#### 3.2 Типи завдань та рівні складності

Для кожної групи результатів навчання додайте завдання різних рівнів складності відповідно до специфікацій у `skills/nush-assessment-generator/references/question-types.md`:

| Рівень | Типи Classtime | Частка |
|--------|---------------|--------|
| Простий | Одиничний вибір | ~40% |
| Середній | Множинний вибір, Заповнення пропусків, Зіставлення | ~40% |
| Складний | Коротка описова відповідь | ~20% |

**Особливості для квізу:** використовуйте лише одиничний та множинний вибір; описові відповіді — лише якщо квіз проводиться не на Classtime.

**Особливості для діагностувальної роботи:** збільшіть частку простих завдань до 60%, щоб виявити базові прогалини.

#### 3.3 Візуальні матеріали

Деякі завдання можуть спиратися на зображення — діаграму, блок-схему, знімок екрану програми тощо. Якщо завдання потребує такого матеріалу:

1. Сформулюйте завдання з посиланням на зображення: `*(див. зображення [N])*`.
2. Визначте, чи є це зображення в репозиторії (у `content/<клас>/assets/`). Якщо є — вкажіть шлях.
3. Якщо зображення потрібно створити — **попросіть користувача його надати** з чіткою інструкцією у такому форматі:

```
> 📸 Потрібне зображення [N]: [коротка назва]
> Зробіть знімок екрану / підготуйте діаграму, що показує:
> - [що саме має бути видно: назва програми, стан інтерфейсу, конкретні елементи]
> - [додаткові деталі, якщо потрібно]
> Збережіть як: content/<клас>/assets/assessments/<тема-slug>/<тема-slug>-img-[N].png
```

4. У Markdown-файлі залиште плейсхолдер на місці зображення:
```markdown
![Опис зображення](../assets/assessments/<тема-slug>/<тема-slug>-img-[N].png)
```

5. Не генеруйте завдання з візуальним матеріалом, якщо зображення відсутнє і користувач не підтвердив, що надасть його — замініть на текстове завдання.

#### 3.4 Оцінювання

- Одиничний вибір: 1 бал
- Множинний вибір: 2 бали (частковий залік не передбачений, якщо не узгоджено)
- Заповнення пропусків: 1 бал за кожен пропуск (зазначте кількість)
- Зіставлення: 1 бал за кожну правильну пару
- Коротка описова відповідь: 3 бали (з критеріями)

---

### Фаза 4: Форматування документів

Генеруйте **два окремих plain Markdown-файли** (без Marp-специфічних елементів): один для учнів (лише завдання), один для вчителя (ключ відповідей та критерії). Не використовуйте `---` між завданнями.

#### 4.1 Документ для учнів

```markdown
# [Тип матеріалу]: [Тема]

**Клас:** [X] | **Варіант:** [1 / —] | **Дата:** ___________
**На основі уроків:** [перелік або "загальна тема"]
**Групи результатів навчання:** [перелік обраних груп]

*Максимальний бал: [N]*

## Група [N]: [Назва групи]

### Рівень: Простий

**1.** ...

- А) ...
- Б) ...
- В) ...
- Г) ...

**2.** ...

- А) ...
- Б) ...
- В) ...
- Г) ...

### Рівень: Середній

**3.** ...

### Рівень: Складний

**4.** ...

*Місце для відповіді:*

_______________________________________________

_______________________________________________

_______________________________________________

## Група [N+1]: [Назва групи]

...
```

> **Важливо:** У документі для учнів **не вказуйте** правильні відповіді, критерії оцінювання чи будь-які підказки. Для описових завдань залишайте лише рядки для відповіді.

#### 4.2 Ключ відповідей (документ для вчителя)

```markdown
# Ключ відповідей: [Тип матеріалу] — [Тема]

**Клас:** [X] | **Варіант:** [1 / —]
**На основі уроків:** [перелік або "загальна тема"]

## Таблиця відповідей

| № | Правильна відповідь | Тип | Бали |
|---|---------------------|-----|------|
| 1 | В | Одиничний вибір | 1 |
...

## Критерії оцінювання описових завдань

**Завдання [N].** [Текст запитання]

- [Критерій 1] — 1 бал
- [Критерій 2] — 1 бал
- [Критерій 3] — 1 бал

**Завдання [N+1].** ...

## Шкала оцінювання

**Загальний бал:** [N]

| Бали | Рівень |
|------|--------|
| ... | Високий |
| ... | Достатній |
| ... | Середній |
| ... | Початковий |
```

---

### Фаза 5: Перегляд та збереження

1. Представте згенерований матеріал користувачеві.
2. Проведіть ітерації — внесіть правки до підтвердження.
3. Після підтвердження збережіть **обидва файли**:
   - Один варіант:
     - Учнівський: `content/<клас>/assessments/<тема-slug>-<тип>.md`
     - Ключ: `content/<клас>/assessments/<тема-slug>-<тип>-key.md`
   - Два варіанти:
     - `...-v1.md` / `...-v2.md` (учнівські)
     - `...-v1-key.md` / `...-v2-key.md` (ключі)
   - `<тип>`: `test`, `control`, `diagnostic`, `quiz`
4. Застосуйте `pre-commit run --all-files` для перевірки форматування.
5. Зробіть коміт та відкрийте PR.

---

## Важливі примітки

- **Мова:** Весь контент — виключно українською мовою.
- **Джерела:** Якщо вказано уроки — використовувати лише їх матеріали, без додаткових понять ззовні.
- **Групи результатів навчання:** Завжди уточнювати у користувача, якщо не зазначено явно.
- **Два варіанти:** Генерувати лише за явним запитом. Питання мають бути різними, але рівноцінними за складністю.
- **Classtime:** Завдання мають відповідати типам платформи (див. `skills/nush-assessment-generator/references/question-types.md`). Описові відповіді перевіряються вчителем вручну.
- **Авторство:** Не вказуйте співавторів, посилань на AI-інструменти у файлах та повідомленнях коміту.
