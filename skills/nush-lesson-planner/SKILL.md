# НУШ Lesson Planner

Цей навик допомагає вчителю інформатики планувати уроки відповідно до стандартів НУШ та створювати презентації Marp на основі шаблону Gaia.

> [!IMPORTANT]
> **Жорсткий gate між Фазою 2 і Фазою 3.** Це стосується *першого* створення або оновлення файлу презентації (`content/<клас>/<номер-уроку>-<тема-slug>.md`) у межах поточної роботи над уроком — байдуже, чи файл новий, чи вже існує з минулих років. Не робіть цього першого запису, поки користувач явно не затвердив план уроку (наприклад, "затверджую", "ок, зберігай", "все добре") і — якщо в плані є Завдання 1 — поки ви не маєте реального посилання для нього (Фаза 2, крок 5). Мовчазна відсутність заперечень — це не затвердження. Якщо є хоч найменший сумнів, чи план уже затверджено, зупиніться і прямо запитайте користувача, перш ніж торкатися файлу презентації. Це правило не можна обійти навіть якщо здається, що зміст презентації "очевидно випливає" з готового плану.
> Після цього першого гейту подальші ітеративні правки презентації за прямим проханням користувача (Фаза 3, крок 8) не потребують повторного затвердження плану — досить прямої вказівки, що саме змінити.

## Робочий процес

### Фаза 0: Підготовка гілки
Перед початком будь-якої роботи:
1. Переконайтеся, що знаєте клас, номер уроку та тему (запитайте, якщо не надано).
2. Сформуйте назву гілки у форматі `<клас>-<номер-уроку>-<тема-slug>`, де `<номер-уроку>` — завжди двозначне число з лідуючим нулем (наприклад, `01`, `09`, `56`), а `<тема-slug>` — короткий slug теми латинськими літерами з дефісами, утворений транслітерацією української назви або її усталеним англомовним відповідником (наприклад, `8-56-audio-capture`).
3. Оновіть локальний `main` з віддаленого репозиторію, створіть від нього гілку та перейдіть на неї:
   ```bash
   git checkout main && git pull origin main && git checkout -b <назва-гілки>
   ```

### Фаза 1: Збір вхідних даних
Запитайте у користувача наступну інформацію, якщо вона не була надана:
1. **Тип уроку НУШ** (наприклад "Урок засвоєння нових знань", "Урок формування та вдосконалення вмінь і навичок", "Урок узагальнення та систематизації знань" або "комбінований урок").
2. **Номер уроку** (наприклад, "01").
3. **Тема уроку** (наприклад, "Інформаційні процеси").
4. **Клас** (5–12).
5. **Сторінки підручника (обов'язково):** сторінки підручника (PDF, скан або фото) — шлях до файлу (зберігається як `content/<клас>/assets/pages/<файл>.pdf` — ця тека захищена від `make clean`) або самі сторінки. Якщо їх не надано — попросіть і не переходьте до Фази 2, доки не отримаєте. Прочитайте сторінки **перед** Фазою 2 і визначте їхні номери у підручнику (для пункту ДЗ). Номери сторінок ніколи не вигадуйте; якщо їх не видно на сторінках — запитайте користувача. Без сторінок працюйте лише тоді, коли користувач прямо скаже, що для цього уроку їх немає (тоді пункт ДЗ про підручник пропускається).
6. **Додаткові обмеження або побажання** (наприклад, "фокус на практичну роботу", "вступний урок").

### Фаза 2: Складання плану уроку
> [!TIP]
> **Рекомендована модель:** Використовуйте модель, що спеціалізується на **глибокому міркуванні** (Deep Thinking/Reasoning), для створення методично правильних планів уроків.

1. Проаналізуйте тип уроку, обраний користувачем.
2. Виберіть відповідний підрозділ (А, Б, В або Г) з `skills/nush-lesson-planner/references/lesson-structure.md` та дотримуйтесь його таймінгу та етапів.
3. Створіть план уроку **виключно українською мовою**, дотримуючись розділу «Обов'язкові правила змісту» нижче (обсяг, практична робота, ДЗ).
4. **Перш ніж просити затвердження**, збережіть план у файл, щоб користувач міг переглянути його у редакторі:
   `content/<клас>/plans/<номер-уроку>-<тема-slug>-plan.md`
   *(`<номер-уроку>` — двозначне число з лідуючим нулем, наприклад `01`, `56`; `<тема-slug>` — англійський slug назви теми, наприклад `info-processes`; якщо презентація з минулих років уже існує, використовуйте її slug)*.
   Збереження плану у файл **не є** затвердженням і не відкриває gate до Фази 3.
5. Представте план користувачеві: вкажіть шлях до файлу, коротко підсумуйте ключові рішення та питання, що потребують уваги, і попросіть затвердити. **У цьому ж запиті** (якщо в плані є Завдання 1) попросіть посилання для нього — див. «Посилання для Завдання 1» нижче.
6. Проведіть ітерації: кожну правку вносьте одразу у файл плану, а потім знову просіть затвердження — доки користувач явно не підтвердить, що задоволений планом.
7. **Зупиніться тут.** Не переходьте до Фази 3 в тій самій відповіді й не пропонуйте презентацію "заодно" — дочекайтеся окремого явного затвердження плану користувачем **і** посилання для Завдання 1 (якщо воно потрібне). Якщо користувач затвердив план, але не дав посилання — попросіть його ще раз.

**Посилання для Завдання 1** (не потрібне для типу Б):
- **Padlet** — оскільки дошка одна на клас і перевикористовується, запитайте: «Використовуємо ту саму дошку, що й минулого разу (<посилання>)?», якщо посилання вже є в попередніх уроках цього класу; інакше попросіть нове.
- **Classtime** — попросіть посилання на сесію та код приєднання.
- **LearningApps** — URL, надрукований текстом на наданих сторінках підручника, використайте без запиту. QR-код самостійно не розшифровуйте — попросіть посилання в користувача.
- Посилання ніколи не вигадуйте і не залишайте плейсхолдери на зразок `https://padlet.com/...`.

### Фаза 3: Генерація презентації Marp
> [!TIP]
> **Рекомендована модель:** Використовуйте модель, що спеціалізується на **написанні коду** (Coding), для точного генерування Markdown-розмітки та CSS-класів формату Marp.

> [!IMPORTANT]
> Перш ніж уперше в межах цієї роботи над уроком створювати чи редагувати файл презентації, переконайтеся, що: (1) план із Фази 2 вже явно затверджений користувачем окремим повідомленням (крок 7 Фази 2), і (2) якщо в плані є Завдання 1 — ви маєте реальне посилання для нього (Фаза 2, «Посилання для Завдання 1»). Якщо ні — поверніться до відповідного кроку Фази 2 і дочекайтеся відповіді користувача.

1. Прочитайте шаблон `templates/gaia_template.md`.
2. Трансформуйте затверджений план уроку в презентацію Marp, дотримуючись ліміту слайдів і складу презентації з розділу «Обов'язкові правила змісту». На слайді Завдання 1 використайте посилання, отримане від користувача (Фаза 2, «Посилання для Завдання 1»).
3. **Обов'язково повністю скопіюйте всі CSS-класи з блоку `style:` шаблону `templates/gaia_template.md` до нової презентації.**
4. **Обов'язково залиште без змін слайд "🛡️ Пригадуємо: техніка безпеки"** одразу після титульного слайда — він є обов'язковим для кожної презентації і слугує коротким нагадуванням правил з `content/9/01-security-rules.md` на початку кожного уроку. Не видаляйте, не скорочуйте та не переносьте цей слайд.
5. Використовуйте CSS-класи з шаблону для оформлення (див. `skills/nush-lesson-planner/references/marp-mapping.md` для підказок):
   - `.grid-container` для порівнянь або тексту з картинкою.
   - `.task` для практичних завдань.
   - `.card` для виділення важливих понять.
   - `.important-to-remember` для ключових правил.
6. Замініть плейсхолдери у шаблоні:
   - `<REPLACE-WITH-ACTUAL-GRADE>` -> номер класу (у header).
   - `<REPLACE-WITH-ACTUAL-LESSON-NUMBER>` -> номер уроку (у header).
   - `REPLACE WITH LESSON NUMBER` -> номер уроку (у контенті слайдів).
   - `REPLACE WITH LESSON TITLE` -> тема уроку.
7. **Перш ніж просити затвердження**, збережіть презентацію у файл:
   `content/<клас>/<номер-уроку>-<тема-slug>.md`.
8. Представте презентацію користувачеві (шлях до файлу та короткий перелік слайдів) і попросіть затвердити. Проведіть ітерації: кожну правку вносьте одразу у файл, потім знову просіть затвердження — доки користувач не буде задоволений.

## Обов'язкові правила змісту

Це єдине джерело цих правил; `references/` лише посилаються сюди.

### Обсяг і склад презентації
- **Ліміт слайдів:** не більше **12 слайдів**; для типу А (урок засвоєння нових знань) — не більше **14**. У ліміт входять титульний слайд і слайд техніки безпеки. **Слайд ДЗ — окремий і в ліміт не входить.**
- **Склад:** титульний, техніка безпеки, цілі, теорія, Завдання 1 (1 слайд; у типі Б немає), Завдання 2 (2 слайди: Середній + Достатній на одному, Високий — на окремому), а також окремий слайд ДЗ поза лімітом.
- **Не додавайте до презентації** слайди рефлексії та опитування. Питання для опитування та рефлексії залишаються лише в плані (рефлексія — на етапі «Підсумки та рефлексія»).
- **Зміст:** лише головний, найважливіший матеріал уроку. Для типу А додатково дозволено цікавий факт (етап мотивації) та детальніше пояснення нового матеріалу — саме для цього ліміт 14. Якщо матеріал не вміщується — скорочуйте або об'єднуйте другорядне, а не додавайте слайди.
- **План:** такий самий принцип — тільки те, що покривається цими слайдами.

### Практична робота на уроці
1. **Завдання 1 — закріплення теорії** (типи А, В, Г; у типі Б його немає — там немає нової теорії для закріплення). Допомагає закріпити теоретичні знання цього уроку (для типу В — узагальнені знання теми). Інструменти: **спільна дошка Padlet** або **Classtime**; для типу В також **вправа LearningApps із підручника**.
   - У плані додайте підрозділ **«Підготовка вчителя»**: покрокова інструкція та **готовий зміст** — колонки й картки дошки або питання Classtime з правильними відповідями. Для LearningApps — сторінка підручника та посилання з неї.
   - **Padlet — безкоштовний план (Neon), максимум 3 дошки.** Не пропонуйте створювати нову дошку щоразу: вчитель тримає **одну дошку на клас** і перед уроком очищає її та налаштовує під нову тему (назва, колонки/секції, картки-зразки). Доступ для учнів — за посиланням з правом «може писати», без реєстрації.
   - **Classtime** — інструкція, як створити набір питань і запустити сесію; учні приєднуються за посиланням або кодом без реєстрації.
   - Перед Фазою 3 отримайте посилання (Фаза 2, «Посилання для Завдання 1»).
2. **Завдання 2 — практична робота за комп'ютером з рівнями** Середній / Достатній / Високий (у всіх типах уроків). У типі В Завдання 2 може бути індивідуальним або груповим (наприклад, міні-проєкт) — але завжди з трьома рівнями.

**Оцінювання:** за замовчуванням обидва завдання **не оцінюються**. Критерії оцінювання та бали додавайте лише тоді, коли користувач прямо попросить, — у плані в підрозділі «Критерії оцінювання» відповідного завдання (і коротко на слайді завдання); на етапі інструктажу до завдання вчитель оголошує ці критерії учням.

### Домашнє завдання — обов'язкові пункти
Список ДЗ (і в плані, і на слайді `## 🏠 Домашнє завдання`) завжди починається з цих пунктів:
1. **Опрацювати конспект уроку** (конспект — це сама презентація уроку, що містить слайд ДЗ).
2. **Опрацювати матеріали підручника с. ABC–XYZ** — з реальними номерами наданих сторінок (див. Фаза 1, крок 5); для однієї сторінки — `с. 45`; для кількох діапазонів (зокрема в уроках типу В) — `с. 34–38, 45–49`. Плейсхолдер `ABC–XYZ` ніколи не залишайте в готових матеріалах. Пункт пропускається лише якщо користувач прямо сказав, що сторінок підручника немає.

Додаткові пункти ДЗ (за потреби) йдуть після цих.

## Важливі примітки
- **Мова:** Весь контент (план та презентація) має бути українською мовою.
- **Синтаксис:** Віддавайте перевагу Markdown-синтаксису над HTML як у плані, так і в презентації для звичайного форматування (наприклад, використовуйте `**текст**` замість `<b>текст</b>`, `### Заголовок` замість `<h3>Заголовок</h3>` тощо). Водночас у презентації HTML допустимий і за потреби обов'язковий для структурних обгорток, які застосовують CSS-класи з `templates/gaia_template.md` та прикладів із `skills/nush-lesson-planner/references/marp-mapping.md` (наприклад, `<section class="task">` або `<div class="card">`), а також для посилань (див. наступний пункт).
- **Посилання в презентації:** усі посилання в презентації завжди відкриваються в новій вкладці — оформлюйте їх лише HTML-тегом `<a href="<URL>" target="_blank" rel="noopener noreferrer"><текст></a>`. Не використовуйте Markdown-посилання `[текст](URL)`, автопосилання `<URL>` та «голі» адреси в тексті (`https://…`, `site.com`) — Marp сам перетворює їх на посилання, що відкриваються в тій самій вкладці. Правило стосується всіх слайдів, зокрема Завдання 1, Завдання 2 та ДЗ. Перед представленням презентації перевірте, що у файлі немає `](http`, а кожна адреса поза атрибутом `href` загорнута в тег `<a>`.
- **Стиль (План):** План уроку має бути офіційним, структурованим та **не повинен містити емодзі**.
- **Стиль (Презентація):** Презентація має бути візуально привабливою, містити Unicode емодзі, інтерактивні елементи та посилання.
- **Структура:** Завжди перевіряйте наявність обов'язкових розділів (мета, хід уроку, ДЗ).
- **Слайд техніки безпеки:** Кожна презентація повинна містити слайд "🛡️ Пригадуємо: техніка безпеки" одразу після титульного слайда (успадковується з `templates/gaia_template.md`). Він не залежить від теми уроку — не редагуйте його вміст.
- **Практичні завдання**: Див. «Практична робота на уроці» вище. Практичні завдання будуть виконуватися за компʼютерами з ОС Windows 10/11. Намагайтеся використовувати безкоштовне ПЗ, що не вимагає реєстрації, або онлайн-інструменти, якщо не зазначено інакше.
- **Ітерації:** Будьте готові до кількох раундів правок
- **Порядок затвердження:** Перший запис у файл презентації (створення нового файлу або оновлення вже наявного з минулих років) не відбувається, поки план уроку не затверджено користувачем явно окремим повідомленням та поки немає посилання для Завдання 1, якщо воно потрібне (див. gate на початку файлу та крок 7 Фази 2). Подальші правки презентації за прямим проханням користувача в межах ітерацій Фази 3 повторного затвердження плану не потребують.
- **Авторство:** У всіх матеріалах (план, презентація, повідомлення коміту, опис PR) **не вказуйте** співавторів, посилань на Claude Code або будь-які AI-інструменти.
- **Джерельні PDF підручника:** Зберігайте лише в `content/<клас>/assets/pages/` і ніколи не комітьте в git — повний опис конвенції в `CLAUDE.md` (розділ «Content Structure»).
